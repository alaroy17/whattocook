# Что готовим

PWA-дневник еды для двоих: рецепты, история приготовлений, календарь, планировщик недели,
список покупок и стоимость блюд. Приложение статическое — живёт на GitHub Pages, а вся база
хранится одним JSON-файлом в вашем Google Drive.

## Что умеет

Пять вкладок: **Сегодня**, **Неделя**, **Календарь**, **Дома**, **Ещё**.

- **Подсказка дня** — алгоритм считает, что вы давно не готовили, и учитывает оценки,
  избранное, наличие продуктов дома и «не три супа подряд». Блюда, приготовленные недавно,
  не пропадают молча — они собраны в отдельный сворачиваемый список.
- **Случайное блюдо** — взвешенный случайный выбор: разнообразие без нелепых предложений.
- **Постоянные блюда** — то, что едите регулярно (салат с рукколой, омлет). У них свой ритм
  «раз в N дней» и отдельная полоска на главной: одно нажатие — и запись в истории.
  В общие подсказки они не лезут.
- **Настраиваемые разделы** — выпечку и заготовки можно выключить, свои разделы добавить,
  порядок задать вручную. Скрытие убирает раздел из фильтров, но не трогает сами блюда.
- **Рецепты** (вкладка «Ещё») — ингредиенты, шаги, время, порции, сложность, теги, фото,
  ответственный повар, отдельные оценки Саши и Андрея, заметки. Фильтры собраны в одну панель.
- **Календарь** — месяц с цветовой кодировкой разделов и точками поваров плюс режим «Лента»
  с фотографиями; тап по дню показывает, что ели, с комментариями и стоимостью.
- **Неделя** — компактный план: каждый день одна строка, блюдо добавляется в два нажатия,
  отметка «приготовили» переносит запись в историю.
- **Список покупок** — собирается из запланированного, группируется по отделам магазина,
  вычитает то, что уже есть дома, и считает сумму.
- **Дома** — холодильник как обычный чек-лист: быстрый ввод, отметки в один тап, подсказки
  «обычно берём». Если список давно не трогали, приложение напомнит — на главной и точкой на вкладке.
- **Продукты и цены** — каталог с ценой упаковки; из него считается стоимость блюда и порции.
- **Статистика** — топ блюд, категории, кто чаще готовил, траты по месяцам, «давно не готовили».
- Саша и Андрей различаются цветом и фигурой на аватаре — видно с одного взгляда, кто готовил.
- Тёмная тема, работа офлайн, установка на телефон как приложение.

## Как запустить у себя

### 1. Репозиторий и GitHub Pages

```bash
git init
git add .
git commit -m "Что готовим"
git branch -M main
git remote add origin https://github.com/<логин>/WhatToCook.git
git push -u origin main
```

В настройках репозитория: **Settings → Pages → Source → GitHub Actions**.
После первого пуша workflow сам соберёт проект и опубликует его по адресу
`https://<логин>.github.io/WhatToCook/`.

Имя репозитория может быть любым — workflow подставляет его в `base` автоматически.
Репозиторий можно сделать приватным: GitHub Pages для приватных репозиториев доступен
на платных тарифах, на бесплатном придётся оставить репозиторий публичным. Секретов в коде нет:
Client ID не является секретом, а данные лежат в вашем Drive.

### 2. Доступ к Google Drive

Приложение обращается к Drive напрямую из браузера, поэтому нужен свой OAuth Client ID.

1. [Google Cloud Console](https://console.cloud.google.com/) → создайте проект.
2. **APIs & Services → Library** → включите **Google Drive API**.
3. **APIs & Services → OAuth consent screen**: тип **External**, заполните название и почту.
   В **Test users** добавьте оба ваших Google-аккаунта. Приложение можно оставить в статусе
   Testing — этого достаточно для двоих.
4. В списке областей доступа добавьте `https://www.googleapis.com/auth/drive` и
   `https://www.googleapis.com/auth/userinfo.email`.
5. **Credentials → Create credentials → OAuth client ID → Web application**.
   В **Authorized JavaScript origins** добавьте:
   - `https://<логин>.github.io`
   - `http://localhost:5180` (если будете запускать локально)
6. Скопируйте Client ID и вставьте его в приложении: **Ещё → Настройки → Client ID → Подключить**.

При первом входе Google покажет экран «приложение не проверено» — это нормально для проекта
в статусе Testing, нажмите «Дополнительно» → «Перейти».

> Почему запрашивается полный доступ к Drive, а не узкий `drive.file`: под `drive.file`
> приложение видит только те файлы, которые само создало **у конкретного пользователя**.
> Второй человек тогда не смог бы открыть общий файл базы и фотографии. Файл база использует
> ровно один, он помечен своими `appProperties`, и весь код лежит перед вами.

### 3. Общий доступ для второго человека

После подключения: **Настройки → Открыть доступ второму человеку** → введите его Google-почту.
Приложение выдаст права на папку «Что готовим» целиком и отправит приглашение.

Второй человек открывает тот же адрес сайта, вставляет **тот же Client ID** и подключается своим
аккаунтом — приложение найдёт общий файл само.

### 4. Установка на телефон

Откройте сайт в Chrome (Android) или Safari (iOS) и выберите «Добавить на главный экран».

## Как хранятся данные

На Google Drive создаётся одна папка **«Что готовим»**, а в ней:

```
Что готовим/
  what-to-cook.json   ← вся база: рецепты, история, продукты, настройки
  Фото/               ← фотографии блюд
```

Папка создаётся сама при первом подключении. Второму человеку открывается доступ к папке
целиком, поэтому отдельно раздавать права на файл и фотографии не нужно.
Локально база дублируется в браузере, поэтому приложение открывается мгновенно и работает офлайн.

Синхронизация: при открытии, при возврате на вкладку и через пару секунд после правки приложение
скачивает файл, **сливает** его с локальной версией и загружает обратно. Слияние идёт по каждой
записи отдельно — побеждает та версия, у которой свежее `updatedAt`. Удаления помечаются полем
`deletedAt`, чтобы доехать до второго устройства; такие «надгробия» вычищаются через 120 дней.
Одновременное редактирование одного и того же блюда с двух телефонов — единственный случай,
когда одна из правок потеряется.

Резервная копия: **Настройки → Скачать резервную копию** (обычный JSON, читается глазами).

## Разработка

```bash
npm install
npm run dev      # http://localhost:5180/WhatToCook/
npm run build    # сборка в dist/
npm run preview  # проверка собранной версии
```

Иконки генерируются скриптом `scripts/gen-icons.mjs` при сборке — файлов картинок в репозитории нет.

## Структура

```
src/
  lib/       база, слияние, Google Drive, алгоритм подсказок, разделы,
             холодильник, стоимость, список покупок
  components/ переиспользуемые элементы и формы
  pages/     Today, Plan, Calendar, Fridge, More, Recipes, RecipeDetail,
             Stats, Products, Settings
  sw-template.js  шаблон service worker, список файлов подставляется при сборке
```
